# 아키텍처

이 문서는 현재 구현과 목표 구조를 구분한다. 일정은 [로드맵](roadmap.md), API 동작은 [API 계약](api-contracts.md), 픽셀 규칙은 [렌더링 명세](rendering-spec.md)를 따른다.

## 원칙

게임은 Rust 코드로 작성한다. 플랫폼과 렌더링 구현은 공개 진입점 뒤에 두고 게임이 특정 백엔드 API에 의존하지 않도록 한다. 선택 기능은 필요할 때만 활성화한다. ECS와 에디터는 필수가 아니다.

## 현재 구조

```text
게임 → rust-pixel-engine → rpe-core → rpe-input, rpe-math
                         → rpe-platform → winit, rpe-input
                         → rpe-input
```

`rpe`의 Builder가 설정을 검증하고 런타임을 생성한다. 런타임은 winit `ApplicationHandler`로 창과 이벤트를 처리하며 `Context`와 게임 객체를 소유한다. `rpe-platform`은 창 속성, 이벤트 루프와 물리 키 변환을 제공한다. 렌더링·자산·게임 프레임워크 크레이트에는 아직 구현이 없다.

### 실행 흐름

1. Builder가 크기를 검사하고 이벤트 루프를 실행한다.
2. 플랫폼 재개 시 창을 생성하고 `Game::init`을 호출한다.
3. 창 이벤트가 입력 상태와 크기·포커스를 갱신한다.
4. 예약된 시점에 시간을 갱신하고 `Game::update`를 호출한다.
5. 입력 전이를 지우고 다음 갱신까지 대기한다.
6. 종료 요청 또는 이벤트 루프 종료 시 초기화된 게임을 정리한다.

중단 시 입력을 해제하고 갱신을 멈춘다. 재개 시 시간 기준을 재설정한다. 게임 생성에 실패하면 게임 객체의 `shutdown`은 호출하지 않는다.

## 목표 구조

```text
게임 → rpe (구성, 생명주기, 백엔드 선택)
       ├─ core / input / platform / math
       ├─ render (공통 프레임과 명령)
       │  ├─ CPU
       │  ├─ GPU
       │  └─ Hybrid (CPU 래스터화 + GPU 표시)
       ├─ assets (이미지 저장소)
       └─ 선택 시스템: world, animation, tilemap, physics, audio, ui
```

그림은 사용 관계를 나타낸 개념도다. 실제 Cargo 의존성은 backend가 공통 `render`를 의존하며 `render`가 구체 backend를 의존하지 않는다. `assets`는 `render`를 의존하지 않는다. `rpe`가 구체 구현을 조립하고 하위 크레이트는 `rpe`에 의존하지 않는다.

게임은 프레임에 명령을 순서대로 기록하고 선택된 backend가 실행한다. CPU는 메모리에서 래스터화하고 GPU는 같은 명령을 GPU에서 실행하며 Hybrid는 CPU 결과를 GPU로 표시한다. 공통 명령과 이미지 조회 경계는 구현 단계에서 소유권과 오류 전파를 검증해야 한다.

## 소유권과 실행 경계

이벤트 루프와 창 작업은 플랫폼이 요구하는 스레드에서 수행한다. 런타임은 게임과 Context를 소유하고 콜백 동안 가변 참조를 빌려준다. 추후 프레임 명령은 해당 프레임 실행 동안만 유지한다. 자산 저장소는 이미지 데이터를 소유하고 세대가 포함된 핸들로 참조한다. 오래된 핸들은 오류로 처리하며 프레임 실행 중 데이터 제거와 충돌하지 않게 한다.

GPU surface와 창의 유효 기간, backend 초기화 오류, suspend/resume 및 크기 0 처리는 005·006에서 검증한다. 일률적인 `Send`/`Sync` 제약은 부과하지 않는다.

## Feature와 정리 작업

현재 `rpe`는 `cpu`를 기본 feature로 선언하고 `gpu`, `hybrid`, 게임 시스템 feature를 정의한다. 선언은 구현 완료를 뜻하지 않는다. `rpe-assets`는 필수 의존성이며 PNG feature가 기본 활성화되어 경량 기본 설치 목표와 다르다. 004에서 선택 의존성을 정리한다. `rpe-platform`의 `window` feature는 winit을 선택적으로 선언하지만 소스는 무조건 참조한다. 지원 feature 조합과 조건부 컴파일은 008에서 검증한다.

## 오류와 호환성

현재 설정·플랫폼·게임 초기화 오류는 `EngineError`로 전달하고 가능한 경우 원인을 보존한다. 새 시스템도 복구 가능한 오류를 명시적으로 반환한다. 0.x 개발 중 공개 API는 변경될 수 있으며 008에서 호환성과 지원 플랫폼을 검토한다. 테스트가 존재하는 것과 대상 환경에서 검증된 것은 구분한다.
